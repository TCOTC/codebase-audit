# 修复与架构调整手册

本文件覆盖三种「非只读」工作模式：**修复模式**（改代码）、**架构调整模式**（改结构）、
**验证模式**（复核既有发现的处理结果）。

层面定位与权威源见 [全栈层面地图](./stack-map.md)；发现有效性的审查见 [挑战门](./challenge-gate.md)。

---

## 0 授权边界（先读，不可跳）

**审计结论不是修改授权。** 收口一份缺陷报告之后、动手之前，必须由用户明确要求修改。
用户未要求时，本手册的用途只是「把建议写得更可执行」，不得据此改动任何文件。

进入修复模式后，仍受两重约束：

- `SKILL.md` 的「修复时的硬约束」（禁用 `pnpm build`、不编译内核、改 Go 跑 `gofmt`、改 `app/` 跑 `pnpm run lint` …）
- 目标仓库的 `AGENTS.md`（尤其加密笔记本兼容性、i18n 规范、可配置项登记、API 契约）

> 注意区分两个仓库：**目标仓库**（`AGENTS.md` 禁止擅自 `git commit`）与 **本 skill 仓库**
> （每次改动后**必须**提交推送）。两者规则相反，不要互相套用。

## 1 修复前：爆炸半径

动手前回答四个问题，答案要写进报告。这不是形式主义——上一轮报告里「建议」写错方向的那条，
就是漏了第 2 问。

1. **谁调用**：grep / 语言服务列出**全部**调用点。只看到一处就改签名，会把其它入口打断。
   尤其注意语言服务结果为空的情况：可能是符号被字符串引用（反射、路由注册、模板）。
2. **谁消费这个值**：值最终写到哪（磁盘 / 网络 / DOM / 用户屏幕）。
   **消费端可能读的是另一个字段**——实测：汇总列修复保留原始 `content` 量纲、只覆盖
   `formattedContent`，两条消费路径各取所需字段，只看实现是否与建议一致会误判为「没修」。
3. **跨端 / 跨设备 / 跨角色**：是否影响其它设备（同步）、其它角色（只读、发布、读者）、
   其它平台（Windows / macOS / Linux / 移动端 / 浏览器扩展）。
4. **是否不可逆**：写盘、删除、加密、迁移属不可逆。此类动作必须
   ① 在任何守卫**之前**被拦住，② 失败时**保留原始数据**，③ 有回滚或恢复路径。

**「照抄另一处实现」是最危险的修法**。先确认两处的上游消费方是否相同：
兄弟路径返回普通 error、经上游映射为 500 时，照抄会把「成功的幂等重试」变成服务端故障——比原缺陷更糟。

## 2 变体分析：先扫再改

同一缺陷几乎不会是孤例。**改之前**用判据 A / D 的机械手段扫一遍同类，
否则会只修报告里那一处、留下同族，下一轮再被报一次（这正是本仓库历史上重复报告的产生方式）。

三种扫法：

| 扫法 | 对象 | 手段 |
|---|---|---|
| 同函数族 | `switch` 同族分支、同名前缀的 `calc*` / `render*` / `is*` | 逐项 diff **判定条件**而非只看分支体 |
| 同集合 | 白名单、枚举、注册表、可用性判定 | 机械提取后与权威源取差集 |
| 同结构 | 结构性特征（如 `LoadAndDelete(` 后无 `else`、`float64(count*100/len(...))`） | grep 特征串，再逐处读 |

命中结果二选一：**纳入同一次修复**（同一提交、同一测试）或**明确列为后续项并写进报告的「未尽事项」**。
不允许沉默略过。

## 3 修法阶梯

按优先级选择，但**不要越级**——能第 1 级解决就不要跳到第 5 级。

| 级 | 手段 | 适用与代价 |
|---|---|---|
| 1 | **收敛到单一真源** | 字面量 / DTO / 键集合在 ≥2 处重复且语义同一（判据 A、D3c）。成本低，收益随重复处数增长 |
| 2 | **加编译期载体** | 常量、类型、枚举、`*bool` 区分「未设置」。**载体强于断言**：断言会被绕过，编译错误不会 |
| 3 | **让非法状态不可表达**（poka-yoke） | 把「记得调用 X」变成「不调用就构造不出来」。适用钱、权限、删除、迁移、流水线等失败静默的场景 |
| 4 | **加运行时守卫** | 位置必须在**副作用之前**；返回语义要正确（不可为返回码照抄兄弟路径） |
| 5 | **改架构** | 仅当 1–4 都不足以防止复发时（见第 4 节） |

**最小修复原则**：不顺手重构、不改无关格式、不把「一致性清理」混进缺陷修复。
混在一起会让回归归因变难、让 review 变贵，出问题时也无法单独回滚。
若确需连带清理，**拆成两个提交**。

**修法也要过挑战门**：特别是当建议形如「照抄另一处实现」或「加一个校验」时，
问「这个修法会不会把一种错误换成另一种更坏的错误」。

## 4 何时该改架构（判据）

出现下列**任一条**，局部修补不足，应升级为架构调整：

- 同一类缺陷在本仓库**已复现 ≥3 次**（查 `references/evidence.md` 的历轮表与已提 issue）
- 该集合**没有任何编译期载体**，且分散在 ≥3 处（例：同一键集合在运行时配置、持久化 struct、
  契约 struct、前端类型四处各一份）
- 正确做法需要人**记住**而不是**不可能做错**（如每个新路由都要人工记得挂只读守卫）
- 修复必须同时改 ≥4 个文件才能自洽 —— 说明缺少中间抽象
- 守卫的挂载**结构上无法断言**（契约类型只有 Method/Path/Handler，容不下中间件声明）

**架构调整的最低要求**（缺一不可）：

1. 先给出**可判定真假的不变量**，例如「petal ⊆ app ⊆ kernel 的 action 集合」、
   「各类型计数之和 = 总数」、「写后读键集合守恒」
2. 把不变量写成**测试**，并确认它在 **CI 执行集内**（判据 G4）——否则不变量只在本地成立
3. 保留**兼容读路径**；格式 / 协议变更要有显式版本与回滚方案
4. 明确**不做什么**：架构调整最容易失控的地方是顺手重命名、顺手统一风格

## 5 验证闭环（阶梯，逐级不可跳）

| 级 | 动作 | 不通过时 |
|---|---|---|
| 1 | 编译 / 格式化：`gofmt`（Go）、`pnpm run lint`（工作目录 `app/`） | 先修，不进下一步 |
| 2 | 跑**受影响包**的单测，并**读全汇总行** | 读全失败清单，不允许用输出尾部代替汇总（曾把 13 处写成 1 处） |
| 3 | **该测试是否在 CI 执行集内**（判据 G4） | 不在 → 「已修复」只在本地成立，必须同时报告，不能写 `fixed` |
| 4 | **CI 实际结论**：`gh run list --json databaseId,status,conclusion,headSha` → `gh run view <id> --json jobs` | 提交信息与维护者评论**都不算**；以最后一个引用该 issue 的提交的 CI 结论收口 |
| 5 | 端到端：从**用户可见入口**走一遍报告里的「业务表现」路径 | 实际表现 ≠ 预期表现则未修好 |
| 6 | 回归测试的写法检查 | 见下 |

**回归测试的两条硬要求**：

- **两侧都要调用真实代码**。验证「两侧结论不一致」时模拟对侧逻辑，误差正好落在最需要验证的地方。
- 改动过滤器 / 白名单时，必须有**「必须保持不安全 / 必须被保留」的用例**锁住它。
  只测「应放行」不够：某条规则的写法退化（正则能匹配空串）会让**全部候选**被静默过滤掉，
  而报告看起来仍然正常。

**先排除噪声再判定回归**：本机平台差异（注册表、换行符）与既有失败（判据 G3 的桩过时）
会伪装成回归。判定前用 `git log -1 --format=%ad -- <file>` 核对改动时间是否落在修复窗口内。

## 6 高危改动清单

下列改动面出错代价高，每项给出必做步骤。**未列到的改动面按 `AGENTS.md` 处理。**

| 改动面 | 必做 |
|---|---|
| 同步忽略集合 | 读 `AGENTS.md` 兼容条款；确认不会让其它设备签出时**删除文件**；加密笔记本与快照格式一并核对 |
| 加密笔记本格式 / AAD / 密钥派生 | 显式格式版本 + 兼容计划；迁移须认证源数据、保留恢复材料、失败可恢复；**不得重新生成 MasterSalt 或丢弃密钥**；用上一版格式夹具覆盖读 / 导出 / 历史 / 备份 / 恢复 |
| 快照 / 仓库格式 | 保留既有快照可读；同步 `docs/WORKSPACE.md` |
| i18n 键 | 加在对象**顶部**；`_kernel` 在**末尾**追加下一个整数键；tab 缩进；全部语言真翻译；保留占位符位置与动词；跑 `python scripts/check-lang-keys.py` |
| 用户指南 / 文档 | 遵守 `docs/SY-FORMAT.md`；**快捷键变更必须在同一次改动里更新文档** |
| API 契约 | `kernel/apicontract` 定义 + `contractHandler` 绑定；`legacy_routes.json` **只删不增**；跑 `pnpm run api:generate --petal ../../petal` 与 `api:check`；同步 petal 声明 |
| 可配置菜单 / 停靠项 | **同一次改动**更新 `app/src/config/entryVisibility/catalog.ts`（类型、层级、标签、默认位置、Simple 默认）与相关测试 |
| 新增可选布尔配置 | 用 `*bool` + `omitempty`；老配置该对象非 nil，用普通 `bool` 会把存量用户静默改成默认关 |
| 只读守卫 | 先按**有无副作用**分组，再决定是否挂 `CheckReadonly`（纯读端点也挂是保守惯例，「兄弟都有」不是充分证据） |
| 块类型 / 容器能力 | 权威源是上游类型方法；**修法不等于补齐上游全部成员** |

## 7 提交与回读

- 提交信息用 gitmoji + 英文 subject，**格式对齐最近提交**（`git log --oneline -5`）
- 有关联 issue 时，在**标题末尾**附完整 URL（`https://github.com/.../issues/NNN`，不是 `#NNN`）；
  URL 不进正文，也不要编造
- GitHub 写入含非 ASCII 时走**文件式流程**：UTF-8 JSON + `gh api --method <m> <endpoint> --input <path>`，
  写后**逐字段回读**（`--jq .title`、`--jq .body` 分开调用）
- `gh api` 的 `--jq` 只在本地求值，**写入命令不要加 `--jq`**
- **写入命令非零退出不等于失败**：先回读远端状态再决定是否重试；
  盲目重试会造成重复 issue / 评论或重复其它副作用
- 标签可能被静默丢弃（无 push 权限时），**不要为此补发请求**
- **禁止** `git commit` / `git push`，除非用户明确要求；本 skill 仓库例外

## 8 修复报告模板

字段用「字段名 + 一个空格 + 冒号 + 一个空格 + 值」，与主报告条目同格式；**不要用代码块包裹**。

### R1. `<改了什么 + 为什么>`

- **对应缺陷**: 判据 + 编号；主报告条目编号
- **变体**: 同族另 N 处（`file:line`）；本轮一并修 / 列为后续项
- **爆炸半径**: 调用方 N 处；消费端字段或用户入口；跨端影响（无 / 有，具体是什么）
- **改法**: 阶梯第 N 级；**为什么不越级**
- **不变量**: 一条可判定真假的断言
- **验证**: 命令 + 结果；该测试是否在 CI 执行集内；CI 结论（run id + conclusion）
- **回滚**: 出问题怎么退
- **未尽事项**: 明确不做的部分与原因
