> **本文件只在「修改本 skill」时需要读**，审计与修复流程不需要它。

## 追加与整理规范（每轮写回时必须遵守）

本 skill 的载体是多个 Markdown 文件，历史上出过三类问题——**都是「追加时没规矩」造成的**，
而不是内容错。追加任何内容前后按此执行：

1. **先查再写**：`python "<skill-dir>/scripts/skill_self_check.py"`（7 组结构检查，秒级）。
   同时用 `git fetch` + 比对远端，确认本地判据库不是残缺版本（曾发生工作树被回退、基于残缺库去重）。
2. **只追加，不并列**：同一条结论若被后续轮次修正，**就地改写或加显式指针**
   （如「本行为历史结论，已在下一行改判」），不要留下两行各自看似成立的表述——
   按「先读登记表」去重的人只会看到其中一行。
3. **表格内不空行**：追加表格行时不要在图块之间留空行，否则表被切成两张、
   末行渲染成没有表头的表，该行等于从过滤集中消失。
4. **表格行的四种破损形态都要防**（都由 `skill_self_check.py` 的列数/连续性检查拦下）：
   ① **单元格内的 `|` 未转义**（须写成 `\|`）→ 该行被拆成更多列；
   ② **追加行被拼接到上一行** → 表现为 `||`、列数翻倍。两种触发方式：
   用编辑工具把旧行末尾的 `|` 一并吃进 `oldString`；**文件末尾无换行**时 `AppendAllText`
   直接把新内容接到最后一行之后（`changelog.md` 上发生过两次）；
   ③ **行尾漏写 `|`** → 该行只有 2 个竖线、单元格数不足（本轮实际发生：新增一行时忘了收尾）；
   ④ **`oldString` 锚点选在上一条的行中间** → 新内容插入到上一条内部，把它的剩余部分
   甩到行尾变成孤立文本（实际发生：用「第二十二轮的标题」作锚点追加第二十三轮，
   结果第二十二轮的正文被接到第二十三轮条目之后，`：① 起因是…` 成了孤立片段）。
   **④ 的特殊之处是列数检查抓不到它**——孤立文本的列数可能仍然合法。
   防法是**锚点必须包含上一条的行尾 `|`**（即只对上一条的末尾做替换），
   追加后回读上一条的结尾是否仍完好。
   **四种都优先靠列数断言抓**——这正是保留该检查的理由，不要因为「很少出错」而删掉。
   追加前先确认文件以换行结尾，或用 Python 写回并强制补 `\n`。
5. **层级即语义**：`evidence.md` 里每轮是 `##`；只有第 1–11 轮嵌在「历轮已确认的发现」下。
   新轮次写成 `###` 并追加在文件末尾，会因上一个 `##` 恰好是个轮次而被整轮漏掉。
6. **判据与实例分层**：`SKILL.md` 每条判据只留「判据 + 关键信号 + P 编号」；
   完整实证、检查法细节、修法陷阱写进 `patterns.md` 的对应 P 条目。
   **下沉前先确认目标处已有该细节**——删掉 A 处而 B 处没有，等于丢判据。
7. **改完脚本必须跑两个自检**：`test_scan_scripts.py`（脚本行为 + 过滤规则 + 空输入）与
   `skill_self_check.py`（文档结构）。两条都要有**负向验证**（故意注入问题确认能被拦住），
   否则自检只是装饰。**判定「拦住」不能只看期望串是否出现**——PASS 行也含该串，
   必须同时要求退出码非 0 且失败清单里出现该标签。
8. **提交前看 `git status` 与 `git diff --cached`**：Python 自检用 `importlib` 从文件加载模块时会写
   `__pycache__/*.pyc`，一不小心就把字节码提交进仓库（曾实际发生过，已在 `.gitignore` 里排除，
   并让自检设 `sys.dont_write_bytecode`）。
9. **新增 `references/` 文件必须在「参考资源」里挂接**，由 `skill_self_check.py` 双向校验
   （被引用的文件必须存在；`references/` 下的文件必须被引用）。孤儿文件按判据 A 就是「无人消费的定义」，
   实际后果是这一轮写的方法论下一轮没人会读到。
10. **热点区保持精简**：`SKILL.md` 是**每次触发都会加载**的文件，只放「热路径」
    （决策、判据索引、流程、输出格式）。历史、维护规范、误报过滤集、修复细节一律下沉到 `references/`，
    并保证 `SKILL.md` 里有**带触发条件的指针**（「做 Y 时读 X」），而不是只列文件名。
    判断标准：该内容**每次**审计都要读 → 留在 `SKILL.md`；只在**特定模式**下读 → 下沉。
11. **判据字母与 P 编号都不得重复**（自检已覆盖）。
    并行会话撞号过，重复编号会让「按编号查既有结论」这一步给出错误答案。
    **编号只增不重排**：P33 是历史避让留下的空缺，**不要为了整齐而补齐**——
    重排会让 `evidence.md` 里已有的 P 引用全部失效，正是判据 A「把位置编号当身份」的自我违背
    （模式 P16 讲的同一个道理）。
12. **断言的存在性本身也要断言**。自检里的检查若写成 `if m and c: check(...)`，
    正则一旦失配（脚本输出格式改了）整条断言就**静默消失**，自检仍然全绿——
    这是「假成功」在自检自己身上的表现。正确做法是**先无条件断言**「两行都能解析」，
    再比较数值。实测：K5 的容器筛选断言就是这么写的，改坏筛选逻辑后自检依然通过。
    同类问题：负向验证脚本若忘了给自检传仓库路径，**整组冒烟检查会被 SKIP**，
    于是「改坏那个守卫」也测不出来（本轮踩过，用例连续两轮误判为「漏过」）。
13. **写负向验证用例时，先证明用例是承重的**。三项要求，缺一项这条用例就等于装饰：
    - **断言补丁真的生效**：替换串没匹配上时脚本原封不动，自检当然全绿，
      会被误读成「守卫没拦住」。替换后要比对内容确实变了。
    - **断言不能只看退出码**：崩溃也是非 0。要同时断言 stderr 里**没有 `Traceback`**。
    - **用例数据必须能区分两种行为**。实测三例：
      ① `["A.md"]` vs `["A.ja.md"]` 在「只抵消语言匹配的后缀」与「抵消任意 `.md` 后缀」
      两种逻辑下**结果相同**，测不出「语言匹配」这个条件——必须让 `extra` 同时含匹配与不匹配的后缀；
      ② 补丁写成 `X if not lang else Y`，而 `lang` 在该场景恒非空，等于没改；
      ③ 两个重叠守卫无法分别验证（改坏下面那条，上面那条仍兜住），
      此时应**合并为单一守卫**而不是各写一条用例。
    判定「拦住」也要放宽到「该组任一相关断言失败」，不要锚定单一标签——
    同一处退化常被同组的另一条断言先捕获。

14. **脚本的输出路径必须以扫描根为基准，不得依赖 cwd**。“测试结果依赖 cwd 的通过是假通过”。
    `os.path.relpath(p)` 不传第二个参数时以 **cwd** 为基准；当扫描根在另一个盘
    （Windows 上 `d:\...` 与 `c:\...`）时直接抛 `ValueError: path is on mount 'd:', start on mount 'C:'`，
    **整个脚本崩溃、一条结论都输不出**。实测该缺陷在 `scan_a11y_antipatterns.py`（5 处）与
    `scan_i18n_text_expansion.py`（1 处）里长期存在而未被发现，因为自检恰好在与仓库同盘的 cwd 下跑过。
    两个要求：① 统一用 `rel_path(path, roots)` 这类**以扫描根为 start** 的辅助函数；
    ② 自检里加一条**异盘 cwd** 用例（`subprocess.run(..., cwd=<与仓库不同盘的目录>)`），
    并且要同时断言「不抛异常」与「输出里不含绝对路径」——
    后者是必需的：只靠 `try/except` 吞掉异常并退回绝对路径也能“不崩”，但输出不可读。

15. **发现方法学陷阱时，改正重测与记下陷阱是两件事，后者不能代替前者**。
    实测教训：第二十二轮判「组件状态覆盖」时用错了方法（按选择器文本判状态，而 SCSS
    的状态主要写成嵌套 `&:伪类`，选择器文本不含类名），发现后把陷阱写进了层面地图，
    **然后把这一维度整个丢掉了**。正确做法是改正方法重跑——第二十四轮重测后立刻
    得到真缺陷（`.b3-switch` 全仓 0 条 `:focus` 规则）与 462 条候选。
    **“我把这个坑写下来了”不是产出，产出是用对方法后的结果。**

16. **判定逻辑不得写在 `main()` 里**。自检只能 import 模块级函数；逻辑嵌在
    `main()` 内部时，自检只能另写一份副本 —— **测副本等于没测**。
    实测：`scan_focus_coverage.py` 的 `verdict()` 原本嵌在 `main()` 内，
    自检里我自己重新实现了一份，结果真正的实现改坏了也不会被发现。

## 本 Skill 的版本管理（强制）

本 skill 目录是一个独立 Git 仓库，远程为 `origin`（`TCOTC/codebase-audit`）。
**每次修改本 skill 的任何文件后，必须立即提交并推送**，不得只改不推。

这条规则**优先于** `SKILL.md` 与修复手册里的「禁止 `git commit` / `git push`」——
那两处约束的是**被审计的目标仓库**，本节约束的是 skill 自身的仓库。两者规则相反，不要互相套用。

固定流程（在 skill 目录下执行）：

```bash
git add -A
git commit -m "<本次修改摘要>"
git push
```

约定：

- 一次修改一次提交，提交信息说明改了什么（如「新增判据 D4」），不要攒多个改动一起提交
- 推送失败（无网络、需认证、远程有新提交）时，**不要静默跳过**：向用户报告失败原因，并说明本地已提交、待推送
- 若远程已有新提交，先 `git pull --rebase` 再 `git push`；冲突无法自动解决时停下询问用户
- 首次使用若 `origin` 未配置，先向用户索取远程地址再推送
- **推送成功的判据是远端状态**，不是 `git` / `gh` 的退出码或报错文本：
  用 `git rev-parse HEAD` 与 `git rev-parse origin/main` 比对，并看 `git rev-list --left-right --count`

## 编辑本 skill 时容易踩的坑（实测）

- `Get-Content | Measure-Object -Line` **不统计空行**，会把 618 行的文件报成 270 行。
  准确行数用 `[IO.File]::ReadAllText($p)` 数 `` `n ``；`read_file` 与 `Select-String` 的行号才是权威的
- `grep_search` / `file_search` **搜不到本 skill**（它在 workspace 之外）→ 用 `Select-String` 或 `read_file`
- PowerShell 的 `cd` 有时会被工具简化掉；`[IO.File]::ReadAllBytes("相对路径")` 走的是 .NET 进程工作目录
  （不等于 PowerShell 的 `$PWD`）→ 一律用**绝对路径**
- `gh api --jq .body` 的中文在默认控制台会乱码，回读比对要走 Python `subprocess` 取字节后按 UTF-8 解码
- **负向验证的补丁要按函数体打，不要按整串打**：想把 `rel_path(path, roots)` 退化成
  `os.path.relpath(path)` 而做整串替换时，**函数定义行 `def rel_path(path, roots):` 也含这个子串**，
  会被一起改成 `def os.path.relpath(path):` → `SyntaxError`，脚本在 import 阶段就挂，
  后续组根本没跑到。用例“失败”了，但**失败的原因不是你以为的那个**。
  打补丁后除了比对内容变化，还要 `ast.parse(patched)` 做语法自检，并断言
  `def <name>(` 仍在（证明没误伤定义）
- **负向验证的补丁必须真的复现原缺陷形态**：另一个实测陷阱是我给 `rel_path` 加了
  `try/except ValueError` 作为宽裕处理，于是“退回不传 start”的补丁**被 try 吞掉了异常**，
  退化成「返回绝对路径」→ 脚本不崩 → 用例看起来“漏过”。**补丁没复现原缺陷，用例就不承重**。- **正向的负向先行断言要把 `\s*` 包在里面**：`\s*:\s*(?!none)` 中的 `\s*` 可以匹配空串，
  于是 `transform: none` 在「冒号后一格空格」处满足 `(?!none)`（它看到的是 `" none"`），
  `none` 反而被判成「可见变化」。正确写法是 `(?!\s*none\b)`。
  实测后果：**所有“把变化去掉”的声明会被判成“有变化”**，缺口全部消失而脚本照常输出。
- **夹具与断言的标签要逐一对应行号**：写多行模板的夹具时容易把行号算错
  （多行模板占两行），于是“有可见文本的按钮不得被报出”这类断言会指向错误的行。
  建议在夹具里用注释标出每一行是什么，并在断言里引用同一套编号。
